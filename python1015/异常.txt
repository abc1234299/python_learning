
1.语法错误和异常
    语法错误：解释器不能正确解释我的程序
    异常：解释器能正确解释程序，但是运行的过程报错了

2.异常处理
    对异常进行处理并不是将错误规避了，而是当程序运行的时候，出现错误的时候提供解决方案，不终止程序，可以让程序继续执行
    try:
        可能发生异常的代码
    except:
        如果了异常，对异常进行处理的代码

    如果没有发生异常，程序会忽略except中的代码，继续向下执行。
    如果发生了异常，会忽略try中剩余代码，执行except中的代码。 except中的代码执行完毕后，会继续执行程序

3.异常处理底层原理
    当程序执行的过程中，发生了异常，底层会创建一个异常类型的对象，向上抛出
    except可以捕获异常对象，可以在except后面指定捕获异常的具体类型
    语法：
        try:
            可能发生异常的代码
        except 异常类型1 as 变量1:
            异常处理语句1
        except 异常类型2 as 变量2:
            异常处理语句2
        except (异常类型3,异常类型4) as 变量3:
            异常处理语句3
        except:
            捕获处理所有类型异常
    描述：
        	如果没有发生异常，程序会忽略except中的代码，继续向下执行。
        	如果发生了异常，会忽略try中剩余代码，根据异常类型匹配到相应的 except 并执行其中的代码。
        	如果发生了异常，且异常类型无法和任何except匹配，异常将向外传递。
        	一个except可以同时处理多个异常，将这些异常放在一个元组中。
        	最后一个 except 可以忽略异常类型，它将被作为通配符使用。

4.else
    try:
        # 可能发生异常的代码
    except:
        # 如果发生异常，对异常进行处理的代码
    else:
        如果try中代码没有发生异常，将执行 else 中的代码

5.finally
    try:
        可能发生异常的代码
    except 异常类型1 as 变量1:
    except 异常类型2 as 变量2:
    except (异常类型3,异常类型4) as 变量3:
    except:
    else:
        try块中的代码正常执行，没有发生异常后执行的代码
    finally:
        不管是否发生异常，都会执行的代码

    描述：
        如果从执行效果上说，大部分场景，将代码放到finally语句和放到try-except块外效果是一样的。
        finally 语句块是 try-except 结构的一部分，它确保了无论 try 块中是否发生异常，也无论 except 块是否被执行，
            其中的代码都会被执行
        直接放在try-except结构外面的代码只会在try-except结构正常执行完毕后才会执行，
            如果在try块中出现异常且没有被except块捕获，或者在except块中出现了新的异常导致程序终止，
            那么这部分代码将不会被执行。
        所以，我们一般在finally中进行资源的释放以及一些连接的关闭操作。

8.异常传递
    try嵌套
        若内层出现了异常且内层无法处理，会将异常一层一层向外传递，直到异常被处理或程序报错
    函数的链式调用
        沿着函数调用顺序反向进行传递

9.with关键字
    封装了try except finally编码范式，提供了一种简洁的方式确保资源的正确获取和释放
    同时处理可能发生的异常，提高了易用性

    语法
        with 表达式 as 变量
        表达式：对象或者函数的调用 需要返回一个上下文管理器对象(__enter__和__exit__)
        变量：用于存储expression的__enter__方法（一般返回的是对象本身的self）
